# OpenCode event spool: хранение и диагностика

Spooling по умолчанию выключен (`OpenCodeStreamOptions.SpoolDirectory = null`).
При явном включении каталог должен находиться вне checkout и пользовательских
credential stores, в отдельном управляемом хранилище диагностических событий.
Перед постановкой строки в очередь `OpenCodeEventSpool.EnqueueAsync` применяет
`CredentialTextRedactor.RedactDiagnostic`: секреты скрываются до записи на диск.
Spool хранит обработанные native events и не является точной копией исходного
потока. К нему по-прежнему применяются ограничения доступа и диагностического
экспорта; redaction spool не отменяет отдельную проверку экспортируемого bundle.

Каждая перечисляемая подписка создаёт `opencode-events-<GUID>.jsonl`. Reconnect
продолжает тот же файл; новая подписка, включая подтверждение отмены, создаёт новый.
Это исключает совместную запись и смешивание истории отдельных подписок.
`SpoolFilePath`, `GetRecentEvents` и `IsOverflowed` показывают последнюю запущенную
подписку. Завершение более старой подписки не переключает эти свойства обратно.
Снимок и путь доступны после завершения последней подписки.

`IsOverflowed` означает потерю старых событий в bounded buffer, давление очереди
spool или ошибку записи. Это не подтверждение durable записи каждой строки.
Нормальное завершение и отмена ждут сброса принятой очереди; ошибка writer закрывает
канал, освобождает ожидающих producers и остаётся видимой в диагностике.

Политика хранения: сервис сохраняет файлы после закрытия и не удаляет evidence
автоматически. Владелец явно включённого диагностического хранилища должен задавать
ограничение дискового объёма и срок хранения, архивировать необходимые файлы и
очищать только закрытые файлы при остановленных подписках. Автоматическая retention
для этого каталога в сервисе не реализована; без внешней политики объём и количество
файлов не ограничены. Production configuration не включает spool по умолчанию.
Старый singleton spool также не ограничивал объём файла; новая изоляция не является
реализацией disk quota или automated retention.

Публичные сигнатуры сохранены. Конструктор отдельного `OpenCodeEventSpool` по-прежнему
принимает явное имя, а без имени использует `opencode-events.jsonl`. Успешный быстрый
`EnqueueAsync` возвращает false; true сообщает давление очереди/недоступность writer,
а sticky состояние читается через `IsOverflowed`.
