# LLM Work GUI: техническое описание preview

Настольное приложение для Windows на WPF/.NET 10: проекты, модели, аккаунты, сессии и запуски LLM в одной рабочей области.

Приложение поддерживает OpenCode, Cursor ACP и встроенный NativeGateway с адаптерами Codex, Claude Code, Cursor, Grok и Antigravity. Доступность моделей и функций проверяется через установленный клиент. Приложение также содержит интеграции Mirasim и legacy star-cliproxy; их использование зависит от подтверждённых возможностей конкретного окружения.

Команды выполняются из корня репозитория. Этот документ описывает возможности и ограничения реализации; он не является актом приёмки.

## Единое руководство

[Руководство пользователя и администратора](USER_ADMIN_GUIDE.md) описывает все доступные пользовательские сценарии и обслуживание установки: подключение клиентов и моделей, проекты, запросы, разрешения, процессы, резервные копии, восстановление, обновление и диагностику.

В программе нажмите **F1** или кнопку **«Руководство»**. Встроенное окно работает без интернета, содержит оглавление и поиск; текст включается в сборку из того же файла. Копия `USER_ADMIN_GUIDE.md` поставляется рядом с приложением.

## Запуск из исходников

Нужны Windows x64, .NET SDK 10.0.401 с совместимыми patch-обновлениями согласно [global.json](../global.json) и PowerShell 7 для служебных скриптов.

```powershell
dotnet build LLMWorkGUI.sln -c Release
dotnet run --project src/LLMWorkGUI.App/LLMWorkGUI.App.csproj -c Release --no-build
```

Внешние CLI устанавливаются и авторизуются отдельно. Интерфейс запускается без OpenCode и Cursor; запросы через соответствующий backend требуют доступного клиента и входа в нужный аккаунт.

1. Откройте «Проекты» и добавьте существующую папку.
2. Настройте нужный backend и аккаунт, затем проверьте его статус.
3. Обновите каталог моделей и выберите маршрут в рабочей области.
4. Создайте сессию и отправьте запрос. История, состояние выполнения и диагностика доступны в приложении.

Новый проект получает ограниченный класс данных. Внешняя отправка требует предусмотренного приложением разрешения. Импорт NativeGateway создаёт отключённые записи: импорт сам по себе не подтверждает авторизацию или возможности модели.

`Ctrl+K` открывает палитру команд, `Ctrl+1…0` переключает разделы, `F5` обновляет активный каталог, список моделей или CLI-статус.

## Сборка дистрибутива

```powershell
pwsh -NoProfile -File scripts/Publish-LLMWorkGUI.ps1 -Version 0.1.0-preview
```

По умолчанию создаётся self-contained пакет Windows x64 в `artifacts/publish/win-x64`: отдельная установка .NET для его запуска не нужна. Для установки, обновления, отката и удаления используются скрипты `Install-LLMWorkGUI.ps1`, `Update-LLMWorkGUI.ps1`, `Rollback-LLMWorkGUI.ps1` и `Uninstall-LLMWorkGUI.ps1` в каталоге `scripts`.

Порядок поставки и сохранения данных описан в [ADR-0009](adr/ADR-0009-per-user-installer-and-update-channel.md). Границы публичного снимка описаны в [README](../README.md).

## Данные и безопасность

Значения секретов сохраняются через Windows Credential Manager/DPAPI, а прикладные записи используют ссылки на них. Настройки профиля NativeGateway не предназначены для хранения ключей: ключ передаётся именем переменной окружения. Смена профиля и возможности нескольких аккаунтов зависят от клиента; для Codex поддерживается отдельный `CODEX_HOME`, Cursor использует штатный вход клиента.

Неопределённый результат отправки сохраняется для сверки. Приложение не выдаёт выбранный маршрут за независимо подтверждённую идентичность ответа. Неизвестные запросы разрешений требуют явного решения.
