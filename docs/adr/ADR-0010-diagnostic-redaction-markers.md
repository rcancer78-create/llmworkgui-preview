# ADR-0010: Маркеры удалённых значений в диагностике

- **Статус:** Accepted для формата маркеров; release security gate OPEN
- **Дата:** 2026-10-02
- **Связанные документы:** THREAT_MODEL.md §5.1, SECURITY_GUIDE.md §3, ADR-0005

## Контекст

THREAT_MODEL §5.1 требует типизированный маркер `[REDACTED:<kind>]`. Реализованный общий
фильтр использует `[REDACTED]`, а совместимый формат диагностики квот — `***REDACTED***`.
Это расхождение документа и реализации обнаружено при итоговом аудите. Оно не считается
закрытым только потому, что существующие тесты проходят.

## Решение

Разрешить непрозрачные постоянные маркеры `[REDACTED]` и `***REDACTED***` в свободном
диагностическом тексте. Тип секрета не обязателен: общий фильтр распознаёт чувствительные
имена и шаблоны, но не всегда может достоверно установить вид учётных данных.
Маркер не содержит исходного значения, его длины, префикса или хеша. Повторная обработка
не должна восстанавливать исходное значение или дублировать его; нормализация одного
допустимого маркера в другой возможна. Оба непрозрачных маркера могут встречаться в одном
документе. Байтовая идемпотентность подтверждается только для отдельно проверенных путей.

Это изменение касается только представления заменённого текста. Обязательная обработка
перед записью, запрет открытых значений, хранение настоящих секретов в Windows secret
storage и reference-only URN в структурированных полях остаются требованиями ADR-0005.
Маркер не является ссылкой на секрет, результатом его проверки или доказательством
полноты обнаружения. Типизированные маркеры также допустимы, если тип известен.

Стадии `identify → classify → replace → verify` сохраняются; меняется только допустимый
формат результата `replace`. Цена решения — меньше сведений о типе удалённого значения:
ложное срабатывание общего фильтра на `token_count` неотличимо от удаления настоящего
секрета по одному маркеру. Числовые показатели типизированной модели квот хранятся отдельно.

## Ограничения и проверка

Текущий структурный разбор применяется к целому JSON object/array. JSON, закодированный
внутри строкового значения, и JSON с произвольным текстовым префиксом проходят только
существующие текстовые шаблоны. Это ограничение обнаружения; выбор маркера его не устраняет.
При обрезанном private-key блоке фильтр удаляет текст до конца диагностического сообщения.

Проверки: StructuredDiagnosticBoundaryTests (typed/escaped/duplicate JSON, вложенные
исключения, обычные аргументы и идемпотентность), QuotaDiagnosticStorageTests и текущий
строгий аудит. Их ограниченное принятие не заменяет release security gate.

Space Bunny через OpenCode `opencode-go/space-bunny-free`, MAX/plan принял это решение:
`artifacts/remaining-work-20261002/redaction-policy/review-result.json`, session
`ses_f0579db99ffeDP8taXoD8C5nEE`, COMPLETED/0/stop, DIFF_VERDICT PASS. Его условия
редакционного принятия внесены сюда и непосредственно в THREAT_MODEL §5.1.2.
Это requested model/variant внешнего CLI-ревью; native identity этим не доказывается.

Проверка тестов: SecurityAndStorageContractTests не требует типизированного маркера;
StructuredDiagnosticBoundaryTests явно проверяет существующий `SensitiveDataFilter.Placeholder`
(`[REDACTED]`) и его идемпотентность на выбранном пути. Эти assertions совместимы с ADR
и сохранены. Достоверность обнаружения и итоговый security gate рассматриваются отдельно.
