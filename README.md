# LLM Work GUI — preview

Рабочая область Windows для проектов, LLM-клиентов, аккаунтов, сессий и многоэтапных процессов. WPF / .NET 10.

**Публичный preview, не GA.** Это снимок развивающегося проекта. Совместимость живых провайдеров, все сценарии обновления и полная пользовательская приёмка для этого снимка не подтверждены. Исторические результаты разработческой ветки не выдаются за результаты публикации.

## Возможности

- Рабочая область с проектами, сессиями, журналом запусков и диагностикой.
- Адаптеры OpenCode, Cursor ACP и NativeGateway; маршруты и доступность зависят от установленных и авторизованных внешних клиентов.
- Библиотека процессов, версии, адаптация, артефакты и этапы согласования.
- Классификация данных и проверки разрешений перед внешними запросами.
- Локальное хранение SQLite, резервное копирование и встроенное руководство по F1.

Интеграции Mirasim и legacy star-cliproxy имеют отдельные ограничения. Grok Bot отключён до появления поддерживаемого публичного способа авторизации; Grok через официальный Cursor — отдельный адаптер.

## Запуск из чистой копии

Требования: Windows 10/11 x64, .NET SDK **10.0.401** (patch-обновления согласно [global.json](global.json)), PowerShell 7. Для полного тестового набора также нужен Node.js 22: часть тестов запускает собственные подставные CLI на Node.

```powershell
git clone https://github.com/rcancer78-create/llmworkgui-preview.git
cd llmworkgui-preview
dotnet restore LLMWorkGUI.sln
dotnet build LLMWorkGUI.sln -c Release --no-restore
dotnet run --project src/LLMWorkGUI.App/LLMWorkGUI.App.csproj -c Release --no-build
```

Внешние CLI и их авторизация устанавливаются отдельно. Интерфейс открывается без них; реальные запросы требуют доступного клиента, аккаунта и соответствующего разрешения. Начните с отдельного тестового проекта, добавьте backend, проверьте его статус и выберите маршрут. Отправленный запрос может передать данные выбранному сервису и расходовать его квоту.

[F1: руководство пользователя и администратора](docs/USER_ADMIN_GUIDE.md) описывает настройку, хранение, восстановление и работу с приложением.

## Проверки и дистрибутив

Windows CI собирает и запускает шесть наборов: Domain, Application, Backends.Contract, Gateway, Integration и UI. По умолчанию исключены только три группы проверок реальных установленных сервисов и одно сравнение с изображениями конкретного окружения. Остальные UI-проверки сохраняются.

Точные команды, исключения и отдельный визуальный запуск описаны в [TESTING.md](TESTING.md). Прохождение CI не подтверждает работу живых провайдеров или совпадение всех 114 эталонных изображений.

После успешного завершения всех шести CI-групп создаётся self-contained ZIP для Windows x64. Для ручной сборки:

```powershell
pwsh -NoProfile -File scripts/Publish-LLMWorkGUI.ps1 -Version 0.1.0-preview
```

Пакет появляется в `artifacts/publish/win-x64`. Для его запуска отдельная установка .NET не нужна; внешние CLI в пакет не входят. Скрипты установки, обновления и отката требуют проверки на отдельном профиле перед использованием с ценными данными.

## Данные и ограничения

При обычном запуске приложение хранит данные в `%LOCALAPPDATA%\LLMWorkGUI`. Секреты используют Windows Credential Manager/DPAPI или ссылки на переменные окружения. Это не зашифрованное хранилище всей переписки: проекты, история, документы и диагностические экспорты могут содержать чувствительные данные. Проверяйте материалы перед публикацией и сохраняйте резервные копии.

Preview не гарантирует совместимость данных между произвольными версиями, полную доступность всех workflow-сценариев или независимо подтверждённое происхождение каждого модельного ответа. Успешный запуск процесса и выбранное имя модели сами по себе не являются такой проверкой.
